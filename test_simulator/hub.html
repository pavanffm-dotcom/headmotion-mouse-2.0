Phase 16 Architecture: 5 Decoupled Memory Layers

All layers operate with strict bounded token compression and automatic credential sanitization.

MemoryHub.getInstance()
Layer 1 jarvis_chat_memory.json

Conversation Memory

Preserves spoken voice Q&A, chat turns, extracted user facts, and custom naming. Redacts sensitive credentials before disk writes.

Layer 2 Transient In-Memory

Mission Memory

Per-mission isolated state tracking steps, UI actions, verified observations, and involved packages. Generates clean summaries upon mission completion.

Layer 3 jarvis_task_history.json

Task History (Max 50)

Archives completed missions with success/fail metrics and duration. Uses strict FIFO/LRU eviction to prevent file growth and bounds prompt token context.

Layer 4 jarvis_user_preferences.json

User Preferences

Stores explicit user defaults (preferred apps, voice speed, confirmation thresholds) and injects a compact key-value summary into model prompts.

Layer 5 jarvis_app_patterns.json

Learned App Patterns

Tracks repeatable UI navigation paths. Reinforces confidence (+0.1) on success and degrades (-0.25) on failure, auto-pruning unreliable selectors.

Security MemorySecuritySanitizer

Privacy & Credential Scrubbing

Redacts API keys, bearer tokens, OTPs, PINs, and card numbers via regex sanitization before anything is persisted to disk or fed to planners.
